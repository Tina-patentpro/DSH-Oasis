# 项目关联及恢复

## Requirements
- 用户必须显式选择项目并确认；文件可选。零选择必须重新验证 folder 归属，只保存本地关联和操作清单，不下载或生成业务文件。
- Client 项目选择与文件读取错误分开；文件接口失败不能阻止已选项目的零文件关联，Host 仍验证项目归属。
- 解除关联仅在既有导入弹窗中两步确认，不恢复原生设置中的手填绑定 UI。请求携带原 open 的 token 和 settings revision。
- Host 使用当前 Workspace 锁、原 token 冻结的账户/路径与设置 CAS；若当前 Workspace 有活跃/未决生成或导入则拒绝。
- 解除网站关联与同 Workspace 的旧 API 绑定须一次原生 settings.update 完成；其他 Workspace 不变。旧导入令牌全部失效，旧服务/费用确认经 settings revision 校验失效。
- 不删除文件或业务记录，不重算旧哈希或修改审核结论。解除失败不能伪装成功；响应仅含本地 workspaceId 与 unlinked 状态，不带凭据。
- 原始错误不透传；账户/关联/服务映射缺失/未知运行分别给出实际可执行提示。

## Scenarios
- 空项目、未勾选历史文件：关联成功、下载数零、无业务产物。
- 所有下载失败：关联状态仍明确展示；用户确认解除后可选另一项目，原文件/清单保留。
- 旧 token、账户变更、并发 settings revision、运行中生成或导入：解除/旧提交拒绝，不覆盖配置。
- 解除后旧的 API 确认不能继续上传/创建；历史运行仅按其冻结身份观察，不因新关联改变归属。

## R1 并发准入补充（2026-09-25 已批准）
- 同一 Host 的导入、解除、旧绑定写入及所有生成准入共享按 Workspace 区分的互斥；争用立即拒绝，不排队重试。不能以独立 busy Set 加一次仓库状态读取替代。
- 解除等待 settings 持久化时，后来的生成不能准入；生成正在准入时，解除不能提交。准入持久化后由未决运行记录继续保护。
- API 在共享锁和 Repository 准入回调内复核冻结设置 revision，解除后的旧确认不能用于上传/创建。
- 异常释放临界区；不同 Workspace 不共用全局锁；已有文件、审核和历史运行保持。锁不是跨进程保护，不改变单 Host 存储约束。

## 历史多附件兼容（2026-09-26 同范围故障修正）
- 历史 `file_url` 可为单个字符串、以逗号接下一 URL 的字符串或字符串数组。拆分和逐项规范化必须发生在单 URL 信任校验前；普通逗号不拆分，规范化后重复项去重。
- 每个附件独立展示/选择；用历史 ID 和地址摘要标识，不向 Client 暴露原始下载 URL。附件重排不改变身份；下载详情复核所选规范化地址仍在当前同属项目的历史记录中。
- 不把多个地址合成一个请求，不下载未选附件；失效地址拒绝，原来源/路径/凭据/重定向限制不放宽。
- 每页仍是最多 20 条历史记录，展开后响应和票据保留既有 2000 项有界限制，超量拒绝、不静默遗漏；每次导入最多 100 项保持。
- 旧文件、失败清单和成功项保持。实际网站失败根因及新安装行为需要本批人工下载证据，不由离线用例代替。
