# 绿洲专业能力 API 与免费 DSH 工作台商业方案

> 版本：V1.1  
> 日期：2026-08-22  
> 决策状态：商业与产品基线  
> 证据层级：静态方案；不代表 Dify 工作流、DSH 插件或生产环境已经完成运行验证
> V1.1 修订：Dify 专业工作流不向用户收取 Token 或其他运行附加费，只收取 ¥1/¥3/¥5 按次服务费

## 0. 执行摘要

### 0.1 核心决策

绿洲慧写 4.0 采用“**免费工作台获客、Dify 专业能力固定按次收费、平台内部承担执行成本**”的模式：

1. **DeepSeek Harness（DSH）工作台永久免费**，提供本地项目管理、文档管理、通用 Agent 和 Skill 运行环境。
2. **DSH 专用插件免费安装**，负责账户授权、专业能力发现、报价确认、任务提交、进度展示和结果写回。
3. **专业 Skill 免费分发**，只保留任务识别、输入准备和工具调用说明；不可复制的专业逻辑保留在服务端 Dify 工作流中。
4. **现有商业平台继续承担收费和管控**，作为 DSH、外部开发者与 Dify 之间的唯一网关。
5. **现有 Dify 作为专业能力后台**，承载 TRIZ、专利检索、申请文件生成、质量检查和审查意见答复等工作流。
6. **旧网站工作台逐步淘汰**；Web 端仅保留下载、登录授权、充值、账单、开发文档、法律条款和服务状态等必要入口。

### 0.2 收费标准

| Dify 复杂度 | 单次专业服务费 | 默认含义 |
|---|---:|---|
| Basic | ¥1/次 | 短链、已有材料加工、基础检查或单一文档生成 |
| Fast | ¥3/次 | 多步骤生成、跨材料整合、较强一致性检查 |
| Pro | ¥5/次 | 深度推理、检索、TRIZ、多材料综合和高价值决策支持 |

上述价格是用户调用标准 Dify 专业能力时支付的**唯一费用**，已经包含该次工作流的模型 Token、Dify 编排、标准检索依赖、计算、存储和失败准备成本。报价和账单不再展示 Token 费、模型费或运行附加费。人工代理、官费、翻译、客户定制及企业专属数据服务不属于标准 Dify 调用，应作为独立产品另行签约，不能在已确认的标准任务中临时加价。DSH 通用 Agent 如由用户自行配置模型，属于用户与模型服务商之间的独立关系，不属于 Dify 专业服务收费。

### 0.3 一句话定位

> 面向技术开发人员和专利代理人的本地优先专业 Agent 工作台：通用工作免费，专业工作流按成功次数透明付费。

## 1. 背景、目标与边界

### 1.1 用户问题

技术开发人员和专利代理人通常面临以下问题：

- 通用大模型缺少稳定的专利工作方法和输出合同；
- 单个 Prompt 难以复现复杂 TRIZ、检索、撰写和审查流程；
- 研发材料、专利文件、对比文件散落，无法形成可追溯项目链；
- 按 Token 计费使单次专业任务的最终价格难以预测；
- 专业服务定价不透明，失败任务、重复请求和退款规则不清晰；
- 通用 Agent 与专业工具割裂，项目上下文需要反复上传和整理。

### 1.2 商业目标

1. 用免费 DSH 工作台降低首次使用门槛，形成持续分发入口。
2. 用 ¥1/¥3/¥5 的低决策成本实现首次付费转化。
3. 用专业工作流版本、输出合同、证据链和人工门禁形成差异化。
4. 同一商业平台同时服务 DSH 用户和外部 API 开发者。
5. 在固定按次总价中通过模型预算、工作流优化和版本成本门禁建立可持续单位经济模型。

### 1.3 非目标

- 不销售只能在本地看到的 Prompt 或 Skill 文件作为主要收入来源；
- 不重新开发一套与 DSH 重复的项目、文件、会话和 Agent 外壳；
- 不让插件或浏览器直接持有 Dify API Key；
- 不承诺 AI 输出可替代专利代理师、律师或发明人的最终判断；
- 不在首版同时上线全部 14 个专业节点；
- 不自动提交专利申请、审查意见答复或执行其他具有法律后果的外部操作。

## 2. 目标客户与核心任务

### 2.1 技术开发人员

**典型角色**：研发工程师、技术负责人、独立开发者、企业创新团队。  
**核心任务**：

- 调研技术背景和主流路径；
- 识别技术矛盾并生成备选方案；
- 形成技术交底材料；
- 在进入正式代理流程前进行专利初检；
- 通过 API 将专业能力嵌入内部研发流程。

**购买理由**：按次总价透明、无需理解 Token 计费、可编程、结果可直接进入项目文件。

### 2.2 专利代理人

**典型角色**：专利代理师、专利工程师、知识产权顾问、代理机构项目负责人。  
**核心任务**：

- 整理发明材料和技术要素；
- 生成并检查权利要求书、说明书；
- 执行概要检索、全文复检和特征对比；
- 管理发明人确认、版本修改和证据链；
- 进行申请文件终检及审查意见答复准备。

**购买理由**：固定输出合同、文档链路、人审门禁、可追溯引用和可复用项目资产。

### 2.3 付费触发点

用户不是为“聊天”付费，而是在以下时点付费：

- 需要一个满足明确合同的专业交付物；
- 需要调用服务端检索、专业规则或高复杂度工作流；
- 需要将上游材料转化为下一节点可直接读取的主文档；
- 需要可审计的任务版本、价格、来源和结果记录。

## 3. 产品组合与价值边界

### 3.1 免费层：DSH 工作台

免费提供：

- DSH 安装与运行；
- 本地项目、文档和会话管理；
- 通用 Agent 能力；
- 用户自己的模型配置；
- 绿洲专业 Skill 目录与输入准备向导；
- 本地模板、清单、文档阅读和基础整理；
- 专业服务结果的本地保存、查看和继续编辑。

免费层的目标不是直接盈利，而是降低获客成本、形成项目上下文并增加专业服务调用机会。

### 3.2 付费层：专业能力 API

付费对象包括：

- 服务端 Dify 工作流执行；
- 专业提示与规则编排；
- 检索策略和专业文档加工；
- 输出合同校验；
- 任务版本、证据、日志和账单追溯；
- 商业平台的鉴权、任务调度和失败补偿。

### 3.3 企业层：商业增强服务

后续可单独报价：

- 团队账户、角色权限和共享余额；
- 统一发票、月结与消费预算；
- 私有 Dify、专属数据源或私有网关；
- 定制工作流和组织模板；
- SLA、专属支持和审计导出；
- 合法取得授权的专业数据库接入。

### 3.4 核心护城河

| 资产 | 是否放在免费插件 | 商业价值 |
|---|---|---|
| Skill 的任务识别与调用说明 | 是 | 获客、教育、自然分发 |
| 项目模板和输入清单 | 是 | 降低首次成功成本 |
| Dify 工作流、专业 Prompt、校验规则 | 否，服务端保存 | 核心专业资产 |
| 能力版本与输出合同 | 服务端下发摘要 | 形成稳定交付标准 |
| 运行、账单、退款和质量数据 | 商业平台保存 | 风险控制和持续优化 |
| 用户项目原始文件 | 默认本地；调用时按清单上传 | 建立信任和数据边界 |

## 4. 总体业务与技术架构

```text
┌─────────────────────────────────────────────┐
│ 免费 DSH 工作台                              │
│ 项目 / 文件 / 会话 / 通用 Agent / 免费 Skills │
└──────────────────────┬──────────────────────┘
                       │ 绿洲专业服务插件
                       │ 授权、报价、上传确认、任务、结果写回
┌──────────────────────▼──────────────────────┐
│ 现有商业平台                                 │
│ 用户与设备授权 / 能力目录 / API 网关          │
│ 模型与Token成本治理 / 余额结算 / 任务与质量审计  │
└──────────────────────┬──────────────────────┘
                       │ 仅服务端持有 Dify 凭据
┌──────────────────────▼──────────────────────┐
│ 现有 Dify                                    │
│ TRIZ / 检索 / 撰写 / 检查 / OA 等专业工作流    │
└─────────────────────────────────────────────┘
```

### 4.1 架构原则

1. **DSH 原生能力优先**：不重复实现项目、文件、聊天和 Agent 框架。
2. **商业平台是唯一边界**：客户端不直连 Dify，不接触第三方服务密钥。
3. **服务端价格权威**：界面、Skill 和本地缓存不得硬编码最终价格。
4. **本地优先、上传显式**：默认材料留在本地，调用外部服务前展示上传清单。
5. **可追溯而非黑盒**：每次调用记录能力版本、输入摘要、产物、价格和状态。
6. **适配层隔离 DSH 变化**：DSH 目前仍处于开发者预览，核心 API 可能发生不兼容变化，因此不得把业务逻辑散落在 DSH 内部接口中。
7. **固定总价与内部成本隔离**：用户只看到并支付服务费；模型、Token、Dify 和标准依赖成本只在服务端内部核算。DSH 本地通用 Agent 的模型设置不改变 Dify 服务价格，也不得被绿洲插件读取。

DSH 官方将模型、工具、Skills、会话、存储和 UI 等能力都定义为可组合插件，并明确当前仍为快速迭代的开发者预览：[DeepSeek Harness 产品说明](https://deepseek.com/harness/en/)、[DeepSeek Harness GitHub](https://github.com/deepseek-ai/deepseek-harness)。

## 6. 价格、计费和退款合同

### 6.1 价格定义

每一个可售能力必须发布不可变的版本记录：

```text
capability_id
node_code
workflow_version
price_version
complexity: basic | fast | pro
unit_price: 1 | 3 | 5
input_schema_version
output_contract_version
availability
```

旧订单永远保留当时的价格和工作流版本；调整价格必须生成新的 `price_version`，不得覆盖历史记录。

V1.1 虽然仍使用 ¥1/¥3/¥5，但“服务费已包含 Dify Token 和标准运行成本”改变了价格合同范围，因此必须发布新的 `price_version`。历史报价和订单继续按原合同解释，不得通过改文案追溯改变历史订单。

### 6.2 成本边界

¥1/¥3/¥5 是标准 Dify 专业任务的用户侧总价，包含：

- 商业平台鉴权和任务调度；
- Dify 工作流编排服务；
- 工作流使用的模型 Token；
- 标准能力已经声明的检索、解析和工具调用；
- 计算、网络、存储和失败准备成本；
- 结果合同校验；
- 基础任务记录、账单和有限期产物存储。

以下内容不是标准 Dify 调用的附加收费项，而是独立产品或外部法定支出：

- 人工代理、人工复核和客户定制；
- 专利官费、翻译费及其他法定或第三方收费。
- 企业专属数据库、私有部署和定制 SLA。

标准 Dify 报价不得出现 Token 费、模型费、外部运行费用字段或其他附加费。若某工作流必须使用无法被固定价格覆盖的付费数据源，该版本不得进入标准目录；应先优化、调整到更高的既有档位、暂停销售，或者作为独立企业服务另行签约。

### 6.2.1 平台内部成本治理

用户不承担 Dify Token 费用，但平台仍必须按任务准确记录内部成本：

1. 记录能力版本、模型、输入/输出 Token、工具调用、运行时间和内部人民币成本；
2. 为每个能力版本设置模型白名单、最大 Token、最大重试、超时和并发预算；
3. 分别监控成功任务的 P50、P95 可变成本、失败成本和退款成本；
4. 成本数据只对内部运营和质量角色可见，不进入用户报价、账单或插件埋点；
5. 成本超限时通过减少重复生成、缓存、确定性节点、模型分层和早停优化；
6. 优化后仍不满足门槛时，只能发布新的能力/价格版本、调整到更高的既有档位或暂停销售；
7. 已创建并确认的报价不得因实际 Token 增加而补收费用。

平台模型与 Dify 凭据继续由服务端安全配置管理，客户端不需要也不得提供专业工作流模型 Key。

### 6.3 计费状态机

```text
免费预检
  ├─ 缺少材料/人工门未满足 → blocked_precheck，不冻结、不扣费
  └─ 通过 → quote_created
             ↓ 用户确认
          funds_reserved
             ↓
          job_running
          ├─ cancel/technical_failed → funds_released
          ├─ contract_failed         → funds_released + 记录质量事件
          └─ completed_ready/warning → funds_settled
```

### 6.4 可计费结果

| 结果 | 是否收费 | 规则 |
|---|---|---|
| 免费预检未通过 | 否 | 不创建付费任务 |
| 用户在执行前取消 | 否 | 释放冻结余额 |
| 商业平台、Dify 或网络技术失败 | 否 | 自动释放或退款 |
| 输出合同校验失败 | 否 | 不向用户转嫁内部质量问题 |
| `ready` | 是 | 完整交付 |
| `warning` | 是 | 已形成合同内成果，明确披露非阻断风险 |
| `blocked` | 默认否 | 应优先在免费预检或人工门阶段阻断；例外必须另行定义商品合同 |

同一任务的人工确认与恢复属于同一个 `job_id`，不得重复扣费。用户主动创建新的版本或改变关键输入，才生成新报价和新任务。

### 6.5 防重复扣费

- 客户端生成 `idempotency_key`；
- 服务端按“用户 + 能力版本 + idempotency_key”建立唯一约束；
- 重复请求返回原任务，不重复冻结或扣费；
- 账单流水必须关联 `job_id`、`quote_id`、`capability_version`；
- 对账要求：结算金额、退款金额和余额变化可逐笔追溯。

现有商业平台已经具备价格字段、任务 key、工作流创建、异步进度及消费/充值/赠送/退款流水，可作为兼容基础：

## 7. 商业模式

### 7.1 收入结构

| 收入类型 | 阶段 | 收费方式 |
|---|---|---|
| 专业工作流调用 | 首发 | Basic ¥1、Fast ¥3、Pro ¥5，按成功次数结算 |
| 开发者 API 调用 | 首发后 | 与工作台使用同一目录和单价，使用 API Key/组织账户 |
| 团队管理服务 | 成长期 | 月费或年费；成员、共享余额、预算、发票、审计 |
| 专业数据源 | 成长期 | 授权成本透传或独立套餐 |
| 企业定制 | 成长期 | 定制工作流、私有部署、专属 SLA 单独报价 |
| 人工增值服务 | 可选 | 人工复核、咨询或代理服务单独签约，不混入 AI 单次价格 |

### 7.2 为什么首版不推订阅

按次计费更适合当前阶段：

- 用户能直接理解 ¥1/¥3/¥5；
- 尚未掌握稳定使用频率，订阅额度容易设计失真；
- 能直接观察每个工作流的使用、失败和复购；
- 避免“为了不浪费订阅而滥用”或“用不完而流失”。

待形成真实用量分布后，可为团队推出月度账户管理和额度包，但底层仍按 Basic/Fast/Pro 记录消耗，保证成本和产品数据可比较。

### 7.3 单位经济模型

单次贡献毛利公式：

```text
单次贡献毛利
= 工作流服务费
- 支付通道摊销
- 模型 Token 和模型服务成本
- 商业平台与 Dify 计算成本
- 标准检索、解析和工具调用成本
- 存储和带宽
- 失败与退款准备
- 客服支持摊销
```

建议以**包含模型 Token 在内的单次可变成本不高于价格的 30%**作为经营目标，并以“P95 成功任务可变成本不得达到或超过售价”作为首发硬门禁。超过经营目标时，依次采取：

1. 降低无效节点和重复生成；
2. 设置模型分层、Token 上限、重试上限、缓存和早停；
3. 调整能力复杂度或发布新的价格版本；
4. 暂停该版本销售，而不是向已确认任务追加费用或隐藏亏损。

### 7.4 收入敏感性示例

以下仅用于容量和现金流敏感性分析，不是销售预测。假设调用结构为 Basic 40%、Fast 35%、Pro 25%，平均服务费为：

```text
40% × ¥1 + 35% × ¥3 + 25% × ¥5 = ¥2.70/次
```

| 月成功调用量 | 示例月服务费收入 | 按 70%贡献毛利率计算的示例贡献额 |
|---:|---:|---:|
| 10,000 次 | ¥27,000 | ¥18,900 |
| 50,000 次 | ¥135,000 | ¥94,500 |
| 100,000 次 | ¥270,000 | ¥189,000 |

真实经营决策必须按每个能力版本的实际成本、退款率和用户结构重新计算。

## 11. 数据、安全与专业责任

### 11.1 数据原则

- 用户项目默认保存在本地；
- 调用专业服务前展示明确的文件上传清单；
- 服务端只收集完成任务所需的最小数据；
- 用户可查看保留期限并发起删除；
- 日志不记录模型、Dify、数据库或用户的明文密钥；
- 任务记录使用哈希或摘要证明输入版本，不在账单中复制完整专利材料。

DSH 官方说明其默认本地处理用户输入、模型输出、会话、附件和运行记录，但调用外部模型、插件、MCP 或服务时，数据可能由外部服务处理。因此绿洲插件必须在上传前重新建立明确的数据边界：[DeepSeek Harness 数据处理说明](https://www.deepseek.com/harness/en/data-processing/)。

### 11.2 密钥边界

- DSH 通用 Agent 模型 API Key：如用户自行配置，由 DSH 原生凭据机制或用户环境管理，绿洲插件不得读取；
- Dify 专业工作流模型凭据：由平台服务端统一配置，用户和插件不可见；
- 商业平台 Access Token：由 DSH 凭据机制保存；
- Dify API Key：只存商业平台服务端；
- 专利数据源密钥：只存服务端安全配置；
- 插件配置、日志和错误消息不得出现上述明文密钥。

### 11.2.1 内容保留基线

- P0 上传输入和服务端产物默认保留 7 天，用于异步恢复和重新下载；
- 用户可在任务完成后主动提前删除服务端内容，本地产物不受影响；
- 7 天到期后删除正文和附件，账务、任务状态、版本号、金额、时间和脱敏哈希按适用的财务、安全及合同政策保留；
- 若企业合同要求其他期限，报价确认页必须显示该期限，不能静默覆盖个人版基线；
- 删除机制、备份清理周期和实际政策链接必须在 Beta 前完成合规审查。

Dify 官方 API 文档建议将 API Key 保存在后端，而不是共享或保存在客户端，以避免泄露和财产损失：[Dify API 文档](https://docs.dify.ai/api-reference/%E6%96%87%E6%A1%A3%E5%9D%97/%E5%88%A0%E9%99%A4%E6%96%87%E6%A1%A3%E4%B8%AD%E7%9A%84%E5%9D%97)。

### 11.3 专业责任边界

- 所有输出必须注明 AI 辅助生成、材料截止时间、使用的版本和待确认事项；
- 专利检索结果不得宣称穷尽全部现有技术；
- 1-3 不得输出正式 D1/D2 最终认定；
- `warning` 必须解释风险，不得隐藏为正常结果；
- `blocked` 不得继续生成正式法律结论；
- 正式申请、答复或法律意见须由适格专业人员审核；
- 上线前必须完成适用的数据、合同、第三方数据库授权和专业服务边界审查。

## 12. 指标体系

### 12.1 北极星指标

**每月成功写回本地项目的专业产物数。**

该指标同时要求调用成功、合同有效和用户获得可继续使用的项目资产，比单纯统计 API 请求数更接近真实价值。

### 12.2 漏斗指标

- 完成账户绑定率；
- 首个本地项目创建率；
- 首次报价查看率；
- 7 日首次付费率；
- 30 日复购率；
- 单节点用户进入下一节点的比例；
- API 用户月活跃密钥数。

### 12.3 质量与经营指标

- 各能力版本 `ready`、`warning`、技术失败和退款率；
- 重复扣费事件数，目标为 0；
- 价格不一致事件数，目标为 0；
- 账单与任务可追溯率，目标为 100%；
- 每档平均可变成本和贡献毛利；
- 人工门未满足却启动付费任务的事件数，目标为 0；
- 上传前未取得确认的事件数，目标为 0；
- 平均首次产物时间和任务恢复成功率。

### 12.4 指标使用原则

首批 30 天用于建立基线，不根据少量样本承诺增长目标。只有在调用量、用户结构和退款分布稳定后，才确定月度订阅、折扣或赠送额度。

本项目应把 DSH 和 Skills 定位为免费、可传播的“专业服务操作系统入口”，而不是新的付费网站。核心收入来自服务端专业工作流的可验证交付，核心信任来自 ¥1/¥3/¥5 固定总价、无 Token 附加费、上传确认、失败不收费、产物可追溯和人工门禁。

首发应坚持“小目录、强合同、真运行”：先用 1-1、2-6、1-2 验证 ¥1/¥3/¥5 的完整闭环，再扩大到其他节点。任何缺少实际工作流、目标与实现不一致、数据源授权不清或输出合同未验证的能力，都不得为了目录完整而提前销售。
