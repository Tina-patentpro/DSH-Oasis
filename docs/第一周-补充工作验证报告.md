## 3. 实现结果

### 3.1 右栏与原生UI保护

- Entry只注册 `conversation.input.right`，Panel只注册 `shell.overlay`，没有注册 `details`。
- live Slot 返回确认入口为 `list/session`、唯一 occupant `oasis-professional-entry` active；Overlay为 `list/root`、唯一绿洲 occupant `oasis-professional-panel` active。
- `details` live 返回仍为 `single/session` 且有原生 active occupant，不含任何 `oasis-professional` ID。
- 真实浏览器RED证明 `ctx.layout.openDetails()`会产生原生遮罩并阻断Overlay点击；最终实现不调用原生Details布局服务。
- normal使用360px插件自有右轨；expanded只读测量原生侧栏边界；hidden卸载绿洲Panel并把焦点返回入口。

### 3.2 项目状态和多页

- Session只通过Workspace `sessionIds`唯一归属解析；不按cwd/path回退。
- Store在Client `apply()`内创建，所有action显式接收Workspace ID。
- 浏览器实测：同Workspace A从A-1切换A-2保持两页；切到Workspace B得到独立单页；返回A恢复原两页。
- 两个工作流均在所选页原位转为“输入材料 + 生成结果预览”骨架；hidden / normal / expanded 与焦点恢复均通过。

### 3.3 Host、构建与分发

- 状态工具只公开 `technical-rd` 与 `cn-invention-patent`；阶段为`week-1-supplement`，能力级别为`panel-shell`。
- clean build生成24.94 kB lazy-CJS Client与37.73 kB source map。
- 插件测试30/30、根级脚本/Skill测试16/16、pack dry-run均退出0；包仅含15个白名单运行文件。
- 两个项目Skill分别由官方 `quick_validate.py` 返回 `Skill is valid!`。
- 一键验证器创建临时Profile、安装产品Bundle与验证专用Host夹具、启动loopback Host、完成RPC/Skill/Slot/浏览器、比较真实Profile并在成功后清理临时根。
