## 3. 关键风险面审计

### 3.1 合同、迁移与数据所有权

- v1 → v2 迁移保留历史字段与旧材料 JSON，不猜测其语义；旧材料必须重新登记后才能参与运行。
- Client 只提交 editable draft；Host 合并并拥有材料哈希、运行、审核、写回与 revision 证据。
- repository 以 Workspace 串行化和 CAS 防止静默覆盖；资源预算在进入 repository 前失败关闭。

### 3.2 路径、TOCTOU 与 no-overwrite

- 材料路径和写回路径均先规范化并限制到 Workspace；拒绝绝对路径、遍历、链接、目录与路径身份漂移。
- 材料哈希前后重检 identity；写回在发布前重新核验父目录和目标不存在。
- 文件采用排他创建；目录仅按本次操作需要逐级创建，失败清理只触碰本次操作拥有的文件和新空目录。

### 3.3 隐私与网络

- 状态和产物只保留材料元数据与 SHA-256；材料正文不存入 Domain Storage，也不进入 local-mock。
- tarball 扫描未发现私钥、常见 API key、个人绝对路径、fixture 正文、浏览器持久化业务数据或 Dify/收费范围代码。
- Week 3 浏览器网络请求全部为 loopback；没有新增外部监听或 Client 直连服务。

### 3.4 UI、无障碍与原生布局

- label/control 关联、状态提示、禁用原因、确认步骤与键盘焦点均有包级或浏览器断言。
- normal/expanded/hidden/narrow 下原生 sidebar 与 conversation 节点身份不变；hidden 下原生 details 仍可用。
- `#root margin-right`、Portal、CSS 变量、observer 和 timer 均由单一布局适配器拥有并在隐藏、异常或卸载时清理。

### 3.5 生命周期与验证器可信度

- 新增 3 个验证器回归测试，分别锁定 Host 关闭、浏览器路径和 schema fixture 兼容性。
- Host 工具注册和 Client 待保存草稿现在都有显式 disposer/flush 门。
- Week 1/2/3 验证器均用新临时 Home，真实 `C:\Users\TinaD\.dsh` 仅作前后强哈希比较。

## 4. 既往审计遗漏反思

此前审计更关注产品合同和主路径，遗漏了“验证器本身是否可移植、是否会挂起、fixture 是否随 schema 演进、注册 disposer 是否被拥有、卸载时未落盘草稿、隐私披露是否与字节读取事实一致、运行状态是否反映当前阶段”等二阶风险。为防止复发，本轮增加：
