# Desktop原生磁盘文件路径桥接修复

本次为已授权后续计划F内的具名兼容缺陷修复，不新增业务界面、来源或真实调用。实施方式沿用户规则：单代理实施，GPT-6.1/max独立审计，不提交/推送；阶段内定向修复不再逐项索要许可。

## 已定位的实际断点

固定签名Desktop2.0.17预加载公开`__DSH_DESKTOP_FILE_PATH__.getPathForFile(File)`，由Electron验证真实File并返回磁盘路径；其客户端未出现对`__DSH_HOST_PATHS__`的适配。固定DSH0.2.0-rc.2输入层读取`__DSH_HOST_PATHS__.pathFor(File)`，不存在时将非图片文件转到临时上传。该层原有实现明确：有磁盘路径的文件/目录生成原生`@path`引用，图片或无路径File走上传。文本/引用的草稿持久化已存在，临时附件ID与Host staged receipt则分别为运行时Map/WeakMap。

## 方案及本次选择

1. **接回原生路径桥接（本次执行者选择）。** 通过固定DSH现有公开`webserver/index-inject`事件，在head加入短的经典脚本，只把既有两名字/方法适配；不获取更多权限、不读文件内容、不依赖绿洲业务或私有store。可解决磁盘非图片文件误入临时上传分支。
2. 持久化所有上传附件/图片：需要浏览器对象、会话持久状态、Host回执冷恢复及权限/消费状态的新协议。不是该桥接缺陷的小型修复，继续保留为原生能力缺口。
3. 由绿洲读私有Map、缓存上传数据或改用文件名猜路径：不符合原生职责/权限边界，不实施。

这不是把上传附件恢复要求改成只保留路径：本次只修其本来就应进入路径引用分支的磁盘文件；图片、无磁盘路径Blob及旧上传芯片的恢复仍未实现、不得据此关闭完整F。

## 最小边界

- 仅在`dshDesktop.protocolVersion===1`且公开原生`getPathForFile`为函数时安装；普通Web环境无操作。
- 已有`__DSH_HOST_PATHS__`时保留原owner，不覆盖或改变它。
- 适配器每次向原生函数传递同一个File对象；空路径和原生异常原样处理，不从名称/相对字符串编造路径，不缓存权限。
- 桥接对象只读；没有文件读写、网络、模型、上传、发送或持久状态写入。原生引用后仍由用户发送，正文读取沿DSH原有权限规则。
- 用DSH已有结构化head script注入，在延迟执行的module启动前安装能力；不改变CSP、浏览器认证、根静态fallback或原生UI单槽。通用Host扩展仅注册该公开事件，读取自己的固定脚本，无新增HTTP接口。
- 只在新旁置Profile加载明确版本`dsh-desktop-host-file-path-bridge/0.0.1`，四项顶层版本、原UI前端/Markdown补丁及签名App保持。新候选另绑扩展/脚本/manifest/锁和公共接点的实际文件，不能就地改旧pin。

**首次路线及修订依据：** 第一版单独链接已变换HTML的前端包，但实际GUI仍走上传。固定`web-app`通过自身`createRequire(import.meta.url)`解析前端，因此Profile前端link未影响实际页面；保存原设计/计划/HTML变换和测试于`.local/oasis-follow-up-20261026/host-path-bridge/html-attempt/`及失败Profile/截图。改用已导出的`IndexInjection`事件，避免改宿主私有解析或根owner。原HTML SHA仍为`2146ac6dd90f5b6f3896d79e6b9a933eaecb6d90525a18f8fabfc364016a5da5`，但不再把未被消费的HTML变换称为修复。

## 验证出口

先保存会失败的适配器执行测试：现成能力接线、普通Web不安装、已有owner保全、原生空路径/异常及幂等只读；另用真实Cordis验证公开事件的head脚本实际可执行。随后最小修复并运行定向回归。

实际GUI须使用同一固定Desktop与公开扩展的新旁置Profile：公开普通/150000字符磁盘Markdown经原生文件选择器进入`@当前文件`引用，不能还显示上传附件；保留已有文本、正常退出重启、A/B归属与文件字节/路径核对，不发送。旧临时上传记录不迁移。即使通过，也仅追加当前文件路径引用出口，不代固定审核版本、全上传类型恢复、业务跨Host/UNKNOWN、U1或新版生成。
