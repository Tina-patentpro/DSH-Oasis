## 实施合同

1. 新建 patent-claims@2，inputSchemaVersion=claims-disclosure-2；四个文字选项卡为技术交底（必填）、附图说明、撰写要求、用户指令。旧 patent-claims@1 和七字段草稿原样读写，目录保留旧版本供历史解析，入口只选新版本。存储容器继续使用 schemaVersion=4，严格校验任务、输入和运行版本配对，不重算历史哈希。
2. 本批 upstream_snapshot 固定为 Host 提供的 missing 状态，明确未接入上游累计文件/正文读取。客户端不能提交上游快照。模型建议不得替换不存在的上游，不声称已完成 14 节点累计合并。
3. Host 严格解析 claims-cumulative-2 十字段 JSON，限制长度、条目数、来源定位和状态；拒绝未知字段、缺项、错误类型、伪造来源、缺失输入的替换。主文档由 Host 生成五个固定章节；时间取实际运行时间并转上海时区，run_uid8 为运行 ID 的 SHA-256 前八位，避免非 UUID 旧 ID 假充 UUID。文件名 claims_时间_run_uid8.md。模型业务建议不等于审核或提交许可。
4. 资源只装配独立公开替身 flow-2-6/public-4e2-1，通过既有只读加载器校验固定清单及四资源指纹。0.2.0 私有文稿不读入运行时、不进入客户端。运行记录仅存合同与指纹，不存指令正文。
5. 两来源复用相同输入与成文函数。本地使用原生离线单次 llm；API 仅合成提供方，不接真实服务。两种隔离模式分别启动，保持互斥。非法结果固定失败，不重试、不自动切换。编辑产物只保留 Markdown，不沿用结构化业务状态作为审核结论；重新审核方可保存和准备对话资料。

## 验证与停点

- 先失败测试再实现：新旧字段/合同配对、来源切换不丢稿、十字段和五章节、缺失上游警示、拒绝异常输出、新文件名、旧记录哈希、资源指纹。
- 定向业务回归；集成后运行一次现有 verify，不扩展监管/诊断工具链。
- 隔离 Desktop：新任务四选项卡、本地公开替身与 API 合成分别验证；编辑再审、无覆盖保存、重启恢复、对话草稿不发送。旧未知运行、旧四版本与保存文件不改。真实 Profile 前后强哈希校验，结束关闭候选。
- 资源/合同失败或模型/真实 API 路由意外出现立即停止该调用；环境障碍仅最小修复。缺少 Desktop 证据则如实报告未完成，不升级本地测试为真实验收。
