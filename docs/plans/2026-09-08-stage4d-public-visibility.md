# 阶段 4D：公开样本的普通产品可见性核查

授权：用户“同意进行4D”。只执行已批准的公开样本检查，单代理；本轮不是独立审计，不授权真实模型/API、私有业务指令、真实 Profile 修改或 Git 提交/推送。

## 目标与范围

检查 4C 最终 Host 原生 llm 接线是否把公开指令标记或提供方错误标记投射到普通产品获取路径。只针对 `PUBLIC_STAGE4C_INSTRUCTION`、`PUBLIC_STAGE4C_ERROR_CANARY` 的真实数据流，不把样本未检出解释为绝对保密。

- 固定 Desktop 2.0.5、内置 DSH 0.1.2-rc.1、Sidebar 0.18.0；沿用项目内隔离候选及现有公开任务。
- 保留四条既有运行、审核、保存内容及 unknown 状态；不新增生成或自动发送对话。
- 只检查本轮必要接点；不建设扫描器、监管器或诊断平台。
- 仓库无 OpenSpec，本文件与一份证据报告承担等价范围/证据记录，不安装工具。

## 执行步骤

- [x] 静态复核客户端 bundle/source map、包清单、Host 指令到模型/结果的接线；记录实际哈希，不修改构建。
- [x] 采集两处真实 Profile 强基线；确认项目内候选、隔离路径及进程/端口独占。
- [x] 启动同一离线候选；检查任务历史、已保存文件、原生对话/详情的普通可见内容，留最小页面证据。
- [x] 导出内容核查：已触发原生 export，命令执行有记录但 UI 下载完成未确认；通过同一原生端点取得有效 ZIP，父子日志非空且 Session 匹配，已检查内容。UI 下载交互另列关注项，不称已通过。
- [x] 核对浏览器实际提供的插件脚本/source map与本地构建，读取已知公开资源路径；不以猜测路由的 404 作为安全证明。
- [x] 关闭候选，复核真实 Profile 与原运行/产物保全；在报告逐项记录通过、失败或尚无证据。

## 判定与停点

- 确定普通路径暴露指令/原始错误时，保留反例并停止对应放行，不删除日志、不篡改输出、不自动转服务端。
- 无法取得必要导出/页面证据则保留该缺口，不因已有 4C 测试通过而关闭门禁。环境问题最多一次必要最小处理，不反复试验。
- npm 包中的 Host 源码与用户通过安装包/调试提取属于已接受剩余风险；浏览器直接获取客户端内容是本轮需检查的普通资源边界。不能把任意 Host 源码都视为应当公开，也不能把管理员读取与普通产品正文入口混同。
- 模型可能复述指令；公开离线提供方不证明真实模型绝不复述。本轮不授予真实私有 Skill 装配或真实调用权限。4E 改变资源装配后须定向核对受影响的可见性，不能复用不同构建的结论。

## 验证方式

Shell 明确为 cmd.exe；PowerShell 仅显式调用现有隔离启动/关闭脚本。使用现有 Playwright CDP 与本地 ZIP 读取依赖，不安装工具。证据放在 `output/playwright/stage4d-20260908/`，报告为 `docs/evidence/2026-09-08-stage4d-public-visibility.md`。代码无变化，不运行整批 verify。权限审查拒绝不得另换通道绕过。

本轮已按公开样本可见性范围完成，状态及限制见报告。两个公开标记未在受查普通内容中检出；真实 Profile、四条运行及保存正文未变化。G-SKILL 对最终私有资源装配仍不自动通过；4E 先做资源来源/加载/打包设计与非秘密等价装配核验，不直接装入私有指令。
