# 账户登录与项目统一保存实施计划

用户已确认五项产品变更、两种来源共用项目目录，以及仅API文件末尾标OIW，并明确要求执行。单代理执行；不提交/推送，不调用真实短信、登录、上传或生成，不改日常DSH。

## 合同

- 产品Host固定生产origin，忽略旧地址/环境/下载来源配置；地址随版本发布。测试可在独立单元边界注入传输，不提供用户环境开关。
- 原生设置保留账户登录（默认短信/密码可选）、本地模型开关及必要项目业务绑定。Host使用既有/api/auth/send、/api/auth/login、/api/auth/pwdlogin；令牌仅由Host存入本插件的DSH credential record，不返给Client。密码/验证码不持久化；错误不回显请求/远端任意正文。退出只清本插件凭据，不登出网站。旧手填JWT不自动转换为新账户。
- 新任务总是local-skill；任务内显式来源选择保留，旧任务来源不迁移。删除默认来源/目录偏好和连接表单，业务提示改为登录。
- 新的统一结果保存默认当前Workspace根目录。名称为权利要求书_时间_v版本.md，API为权利要求书_时间_v版本_OIW.md。名称由Host基于运行来源/时间/版本确定，不由Client伪造。同名拒绝覆盖，不移动/改名历史文件。
- 根目录保存继续使用审核+一次确认，双文件Markdown/追溯JSON配对；新文件使用排他创建。部分发布失败保留可识别证据，不删除不确定归属文件，不假装事务成功；已有子目录记录保持可读。通过现有Sidebar公开文件接口查看/编辑。

## 实施与验证

1. 留存当前脏工作区输入哈希及本批变更前源码；沿用source-promotion既有测试依赖，不安装第三套环境。
2. TDD实现固定产品配置和账户Host/RPC/Client。覆盖登录失败、缺token、凭据保存失败、并发/过期响应、短信冷却、退出、敏感信息不出Host及配置不能改目的地。
3. TDD实现固定新任务来源、删除设置入口、项目根目录与文件名规则；覆盖不同来源同目录、版本后缀、文件碰撞/链接/项目切换、旧记录/哈希保持。
4. 受影响测试通过后在既有隔离源码树完整verify，构建产物同步主目录。保持旧已安装包与pin，部署前需开发副本正常退出并生成当前恢复快照；真实登录另由用户操作。

## 完成界限

源码/合成测试不代表Desktop安装或真实登录成功。首次验收不得消耗此前未细化的费用许可。缺失现网能力时停止对应动作，不使用目标态refresh/device-code接口。所有既有用户修改保留。
