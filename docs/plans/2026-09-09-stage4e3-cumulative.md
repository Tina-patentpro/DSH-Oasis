# 4E 剩余工作：累计文稿与装配边界

用户已批准按上一轮计划执行。单代理；不提交、推送、发布，不使用真实模型/API或私有资源运行，不修改真实 Profile。

## 当前目标与实施决定

1. 保持 `patent-claims@2` 四文字选项卡及两来源共用页面。增加一个当前 Workspace 的上游 Markdown 相对路径确认入口，可取消选择。Host 读取一次确定文件并记录哈希；提交前重读核对。旧材料登记仍是 metadata-only，不自动成为生成输入。
2. 上游限一个 UTF-8 Markdown，最多 64 KiB、24000 字符；身份取实际文件的 Flow-1-5、workflow_run_uid、generated_at 和文件名。缺失/结构异常保留原文并警示；路径越界、重定向、读取变化或超限拒绝。不扫描目录、不回读历史。
3. 增量兼容：旧 `missing/not-connected` 快照与成文行为保留。新运行带独立 compositionVersion 和完整 workflowRunUid，只有新成文使用 UUID 前八位及一致上海时间；原历史哈希不重算。
4. 新累计稿保留上游原文、当前有效内容、四项输入、模型更新与全部继承风险。保留五主章节。替换仅允许唯一来源定位且用户明确写出 `替换：内容ID`；原文和修订记录均保留。无明确指令不得覆盖。全文超限失败，不用摘要或截断冒充完整。
5. 公开替身身份与正式 `flow-2-6/0.2.0` 分离；成文记录实际执行资源，不冒称私有 Skill。补齐输入来源、补齐记录和状态一致性校验，不以此声称专业质量或保密通过。

## 文件边界

修改包内 generation-contract、claims-v2-result、统一/本地生成服务、Workbench 合同/RPC/现有页面与远程调用接点；复用 workspace-materials 路径/哈希保护，不建通用文件系统或解析框架。新增有限上游合同/读取模块和业务测试。按需要重建现有客户端。主计划、AGENTS.md 和本批证据只追加当前状态。

## 验证与停止条件

先记录失败测试，再实现：精确文件读取/变化/越界、完整继承与风险保留、明确替换、新旧成文/哈希和 UUID、两来源保存/再审。集成后一次现有 verify；使用公开样本做受影响 Desktop 操作，不重跑全部 4C/4D。

只补查当前资源的普通文件读取、导出和有效结果复述。若复述反例仍成立，记录 G-SKILL 未通过并停止私有装配，不扩展过滤/诊断工具链。此停点不禁止独立的公开业务实施，但 4E 整体不能标完成。

真实 API 属阶段 5，真实模型与私有内容验收需要门禁及另行授权。本计划不将缺失授权转换为自动调用许可。
