### P2-01 Client 没有完整验证 generic RPC 返回的 Workspace record

位置：

- `D:\OneDrive\4、董娣相关\9、绿洲慧写4.0预研\packages\oasis-professional-service\src\client\workbench-remote.js:12-21`
- `D:\OneDrive\4、董娣相关\9、绿洲慧写4.0预研\packages\oasis-professional-service\src\client\workbench-model.js:19-46`
- `D:\OneDrive\4、董娣相关\9、绿洲慧写4.0预研\packages\oasis-professional-service\src\client\workbench-model.js:49-64`

`unwrap()`只确认 RPC envelope；`assertRecord()`只确认顶层 identity、revision、panelMode、task 顺序和 taskId 映射，没有验证 task 的 `title/workType/workflowId/workflowVersion/inputRefs/formValues/run/preview/review/createdAt/updatedAt`，也没有验证根 `updatedAt`。此外 Host 的 revision schema 只要求非负整数，而 Client 要求 safe integer，两个 wire 合同并非完全一致。

影响：版本错配、错误处理器或异常响应可进入 UI；例如对象型 `title` 会被接受，随后可能触发 React 渲染边界，其他非法字段会在下一次保存时才被 Host 拒绝。generic Connection 的返回类型是 `RpcResult<unknown>`，不能把传输层 envelope 校验当作业务响应校验。

本轮证据：

- `D:\OneDrive\4、董娣相关\9、绿洲慧写4.0预研\docs\evidence\week2-audit-2026-08-25\verification\client-response-validation-probe.test.mjs`
- `D:\OneDrive\4、董娣相关\9、绿洲慧写4.0预研\docs\evidence\week2-audit-2026-08-25\verification\client-response-validation-probe.txt`：exit 1，`Missing expected exception`。

修复要求：为 get record 与 replace result 建立完整、严格、可共享或等价生成的 wire schema；在 model/UI 前 parse；补 nested task、unknown field、时间、revision 上界、conflict union 的 RED/GREEN 测试。
