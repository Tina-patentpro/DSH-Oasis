## 1. Findings first

### P1-01：所谓“隔离包装器”可发生 CMD 参数注入，并且允许把真实 DSH Home 作为写根

**位置**

- `scripts/dsh-isolated.mjs:83-86`：接受任意 `--home`，未拒绝真实 `C:\Users\TinaD\.dsh`、其父目录或其子目录。
- `scripts/dsh-isolated.mjs:100-105`：Windows 下通过 `shell: true` 启动 `dsh.cmd`。
- `tests/scripts/dsh-isolated.test.mjs:40-105`：六项测试没有包含 `& | < > ^ ( ) % !` 等 CMD 元字符。
- `README.md:10`：声称运行被限定到显式隔离 `DSH_HOME`，与实际防护不一致。

**可复现证据**

- `static/wrapper-shell-challenge.txt`：向包装器传入含 `&` 的单个参数，假 DSH 只收到 `safe`，随后 CMD 执行了第二条命令，`injected=true`。
- `static/wrapper-real-home-challenge.txt`：只读执行 `--home C:\Users\TinaD\.dsh --print-home`，退出 0 并原样返回真实 Home。

**影响**

第一周补充报告中 P2-03“参数转发”和 P2-08“真实 Profile 保护”不能维持关闭。插件路径、工作区路径或其他参数一旦含 CMD 元字符，包装器可能执行非预期命令；操作人员误把真实 DSH Home 传给包装器时，后续 `plugin add`、`--dump-config` 等命令会写真实 Profile。

**最小修复方向**

1. Windows 不再通过 `shell:true` 转发参数；优先直接调用已解析的 Node CLI 入口，或采用经过独立元字符测试的严格 Windows argv 编码层。
2. 对写类命令使用 `realpath/lstat` 校验，强制 Home 位于新建的声明式临时根；拒绝真实 `~/.dsh`、其祖先、后代、链接和 junction。
3. 新增包含元字符、空格、Unicode、尾反斜杠和引号的 RED→GREEN 测试。

### P1-02：normal 模式没有为中栏预留空间，实际遮盖中栏内容

**位置**

- `packages/oasis-professional-service/src/client/OasisPanelHost.js:41-46,60-74`：面板以 `position:absolute; right:0; width:360; zIndex:1` 覆盖底层。
- `packages/oasis-professional-service/src/client/panel-geometry.js:6-8`：normal 只计算 Overlay 内右侧矩形，没有调整 DSH 中栏布局。
- `packages/oasis-professional-service/src/client.js:7-40`：运行时只注入 `slots`，没有任何有效的中栏空间预留行为。
- `docs/plans/2026-08-24-dsh-beta-overall-plan.md:52-54`：确认的 normal 合同要求中栏保持可用并被压缩，而不是被遮盖。

**运行证据**

`browser/oasis-panel-normal.png` 中，右栏从约 x=1240 开始覆盖；中栏用户消息和底部输入控件在面板边界被截断。现有浏览器测试只断言面板宽度为 340-380px，没有验证中栏内容仍可见、输入仍可操作。

**影响**

这违反用户确认的“左栏和中栏不动，右栏作为插件工作区域”以及总体计划的 normal 合同。expanded 覆盖中栏是明确设计，normal 覆盖中栏不是。当前 Host/Browser 绿色只能证明面板能显示，不能证明核心三栏协作关系成立。

**最小修复方向**

在不覆盖 `details`、不写 DSH DOM 的前提下重新确认当前版本是否存在官方布局预留能力；如果没有，按总体计划的止损规则暂停 normal 实现，选择“仅 expanded/hidden”临时方案或提出最小上游 Slot/Layout 扩展，不以 Overlay 遮盖代替布局。

### P2-01：多页键盘模型改变选中状态但不移动焦点，跨项目隐藏时焦点目标还会过期

**位置**

- `packages/oasis-professional-service/src/client/PanelChrome.js:38-50`：左右键调用 `onActivatePage`，没有把焦点移动到新 tab。
- `packages/oasis-professional-service/src/client/PanelChrome.js:40-43`：Delete 删除当前 tab 后没有把焦点移到相邻 tab 或合理控件。
- `packages/oasis-professional-service/src/client.js:17`、`WorkbenchEntry.js:12`、`OasisPanelHost.js:48-50`：所有 Workspace 共用一个 `focusTarget`；从 B 返回已展开的 A 后隐藏，目标仍可能指向已卸载的 B 入口。
- `docs/plans/2026-08-24-week1-supplement.md:422-424`：明确承诺页签键盘切换与焦点恢复。

W3C Tabs Pattern 要求左右键把焦点移到相邻 tab，Delete 后把焦点移到后继或前驱 tab；当前实现只改变 React 状态，不满足该交互合同。

### P2-02：总体计划仍保留与最终 Slot 决策冲突的 `openDetails/closeDetails` 方案

**冲突**

- 总体计划 `docs/plans/2026-08-24-dsh-beta-overall-plan.md:7,104-106` 仍要求 normal 调用 `ctx.layout/openDetails`、hidden 调用 `closeDetails`。
- 同一总体计划 `:88,111-113`、项目 Skill `dsh-plugin-development/SKILL.md` 和补充计划 `:310` 又要求不得使用 `openDetails`，因为真实浏览器已证明会产生遮罩并阻断 Overlay。
- 当前代码完全不调用 layout，转而使用绝对定位 Overlay，于是产生 P1-02。

**影响**

总体计划不是可直接执行的单一架构决策，第二周工程师可能恢复已经被证伪的 `openDetails` 路线，或继续叠加当前遮盖中栏的路线。进入第二周前必须先统一计划，而不是从冲突文本中自行选择。

### P2-03：`NATIVE_UI_PRESERVATION_GATE` 的运行证据弱于报告声明

**证据缺口**

- `tests/integration/week1-supplement-browser.test.mjs:100-131` 只在状态切换前查询一次 `details` occupant。
- 隐藏动作发生在 `:160-165`，其后没有再次查询 Slot，也没有打开一次原生 Details 验证可交互。
- 补充计划 `:464` 要求隐藏后重新查询 live Slot，`NATIVE_UI_PRESERVATION_GATE` 还要求隐藏后原生详情行为不变。
- 计划 `:497` 要求 normal、expanded、hidden 和 A/B 截图；实际只有 normal、expanded 两张截图。
- 旧 `closure-audit-final.txt` 只记录 `details_preserved=True` 等布尔值，没有可复现的生成脚本或隐藏后原始响应。

**裁决**

## 2. P3 与非阻断风险

### P3-01：IPv6 loopback 被错误拒绝

`new URL('http://[::1]')` 的 `hostname` 为 `[::1]`，而 `dsh-local-api-smoke.mjs:18` allowlist 写成 `::1`。`static/ipv6-loopback-challenge.txt` 证明请求在 fetch 前被误判为非 loopback。IPv4 验证不受影响。

### P3-02：窄屏与布局退化尚未覆盖

面板 CSS 设置 `minWidth:300`，但几何函数可能返回小于 300px 的宽度；总体计划要求小于 1024px 自动使用 expanded，当前没有实现或测试。该能力属于后续 Beta，但不得宣称响应式门已通过。

### P3-03：浏览器验证通过时页面仍显示一次 Agent 运行失败

验证器为了让临时 Session 出现在项目树中调用 `session.prompt`，同时主动清除凭据并阻断外网，因此截图中出现“本轮运行失败 / no API key”。这不是绿洲面板加载失败，console/pageerror 也均为空，但应在证据报告中明确标成测试夹具副作用，避免将带可见失败的截图描述为无条件产品绿色。

### P3-04：供应链证据仍限定于当前机器

冻结离线安装、build、30 tests 和 pack 均成功；`pnpm list` 在正常权限下也成功。但离线安装复用了本机 store，浏览器测试默认 Playwright 路径绑定当前 Codex runtime，仍没有干净机器下载与另一台 Windows 机器的复现证据。原报告的 OneDrive/pnpm P3 继续保留。
