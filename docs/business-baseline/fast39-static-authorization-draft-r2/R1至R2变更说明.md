# Fast39授权草案R1至R2变更说明

2026-11-05，Asia/Shanghai。R2是待审文档版本，R1及其技术复审结论保留，不补认批准或执行。

| 本轮变更 | R2落点 | 保持的边界 |
|---|---|---|
| AUTH-TR01唯一定位 | 主稿§4.3，机器草案`registry_proposal` | 由含混Flow键改为现有`运行记录=10157`，同时校验Flow、11列表头、行hash、唯一性和语义归属；四字段不增加 |
| 哈希／漂移约束 | 主稿§4.3及STOP03／08 | 固定初始原行hash；仅已证实自身成功事务的后行hash可用于后续本任务事务。外来／未知变化即停；不自动换键或改expected |
| 两处结构恢复 | 独立B主稿及机器草案`exact_changes` | 仅补分隔列、迁位原六单元并去除孤立分隔残片；全部旧事件、原hash／统计／接受和归属不变 |
| 一次性流程例外 | B主稿§2及机器草案`process_exception` | 普通apply不支持结构恢复；明确单次例外原子提交、真实correction及元数据来源，普通工具保留自身生命周期。不伪造原工具回执；未来执行绑定仍待审 |
| A／B／CI授权分开 | 机器草案`authorization_components` | A不暗授B；B不暗授候选生产；正常CI须有自己有效授权。周报不豁免时效 |

静态profile、任务、拟交文件版本和路径中r1／R1有意不改：它们是原拟议静态产物身份，授权文档升为R2不代表产物另建一版，也不代表R1已执行。原1 YML＋3 nodebook＋4证据、9逻辑阶段、六字符串输出、C4／LA与来源hash、Batch局部例外、完整当前候选仍undesignated均保持。

后续仍缺：本包技术复审和明确准确批准；B的准确执行意图／脚本及hash／差异／锁与原子回执绑定；正常周报复盘及新鲜治理0；实际源结构恢复与严格唯一行验证；执行时来源／路径／语义归属及正常started／四字段授权。只批准一个组件不解除其他组件。

本轮只新增R2及核验文档，未改业务代码、源登记册、CI、R1或历史证据，没有部署、生成或付费调用。当前源结构和周报旧FAIL仍保留；文档检查不关闭这些门。
