# PDF正式接入的版本与准入接续 R1

2026-10-29，依据现有DS-03及用户“最小改动、不再扩大实验范围”。这是原 `v340-extraction-1` 的**版本冲突澄清候选**，不是已经启用的产品协议。原提取合同、product-gates及旧候选原字节不修改，不把本补充写成U1/D1通过。

## 1. 修正未来版本占用冲突

原提取合同第5节曾给新提取材料预留 `v340-native-candidate-3`。当前实际 `src/v340-native-contract.js` 已将v3用于M06 0.1.2/0.1.3资源身份；它严格不接受extraction。这是版本命名冲突，不能直接把提取字段塞进现有v3，或重签旧摘要。

| 对象 | 当前/历史 | 后续PDF候选规则 |
|---|---|---|
| 共同表单 | v340-1 | 不变，八输入/两来源同页合同不变 |
| 提取证据 | v340-extraction-1目标 | 字段、双hash、定位、容量不变 |
| inputSnapshot材料标记 | 历史无新标记 | 非空新证据与extracted-text-v1同时存在；不匹配拒绝 |
| 原生候选v1/v2 | 既有严格分支 | 只读/验证历史，不升级或容纳extraction |
| 原生候选v3 | 已有M06身份分支 | 保留其严格schema、资源pin、序列化及请求摘要 |
| 含提取证据原生候选 | 原计划v3命名已占用 | **改为预留v340-native-candidate-4**，承接对应M06身份、材料证据及完整请求摘要；尚未实现 |
| 累计MD | oasis-v340-1现行 | 非空材料证据按原目标oasis-v340-2继承；不删证据降级 |

没有新提取证据的现行M06请求继续v3，不因加载新读取器自动升v4。新v4只在完整inputSnapshot/values/receipt/confirmation/MD读取和保存分支一并具备后启用；不能单改版本字符串。非M06节点的未来v4还须绑定各自已明确的资源身份，不从M06推定。

PDF新文件值仍是原文件名、提取正文、textSHA，加完整Host产生的extraction；rawSHA不替代正文hash。upstream_md_file仍只接受一个明确MD。旧文件/审核/确认不迁移，未知运行不重派；旧安装包无法读新编码时明确拒绝，保留原文件，不能删字段后重新算hash。

## 2. PDF直接缺件，保持原上限

两项[最小试验](../evidence/2026-10-29-pdf-container-minimal-return.md)只证明一个公开PDF提取和一次256MiB下OOM终止。当前缺件限定为以下五组，不追加运行栈或实验矩阵：

| 缺件 | 对应产品边界/交付责任 | 关闭要求 |
|---|---|---|
| 完整文字profile及有界解析 | PDF提取适配器；本项目实现范围，非已指定个人 | 同份字节预检/解析；对象/XRef/过滤器/单流与聚合解码限额、非支持内容拒绝；不能仅靠extract_text非空 |
| 完整执行限制 | 实际固定公共执行机制及其适配；未选定正式分发运行栈 | 硬256MiB、严格文件读取/网络/exec、独立stdout/stderr、5秒/15秒及取消/全程回收；Docker参数不替代未测性质 |
| 可发行组件闭包 | 实际运行时/解析器/适配器分发清单及通知负责人待具名 | 固定实际闭包、来源hash、许可证/通知及runtime/componentTree/adapter指纹；不把旧DOCX XSL缺件施加给PDF |
| 新旧合同接线 | Workspace材料/prepare/native候选/运行快照/累计MD现有边界 | 同份有界原字节、双hash/UTF-16定位、确认失效、快照容量及v1/v2/v3保全；U1前不开放扩展名 |
| API材料能力 | backend/Dify接受的逐字段编码 | 保留完整extraction，不上传原二进制或删除证据求兼容；新文字API合同候选不代此能力 |

具体数值仍完全沿原提取合同第6节，不提高内存、页/对象/解码、原件/正文/快照、输出或时间上限。本轮不补做上述运行验证；它们是尚未完成的正式接入条件，不能因为用户要求简化实验而记作通过。

## 3. 当前入口与接线出口

当前生产.md/.txt入口、来源开关及旧拒绝行为保持；不把公开两页样本作为所有PDF准入证明。U1须固定准确组件/命令并验相应格式，之后才能冻结D1实际补丁，沿 `workspace-materials.js → v340-preparation.js → inputSnapshot/receipts → native/MD` 接线；业务界面沿用已确认方案。API新材料能力独立核对，不自动换来源。

本轮交付是可实施的编码/兼容边界及API文字合同候选。PDF正式提取、Host装配、实际双来源生成、专业/用户验收仍未完成；新Docker/Colima运行、依赖安装、模型/API生成与费用均不在本轮动作内。
