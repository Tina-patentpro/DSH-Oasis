# M06零生成只读预览方案 V0.1（待确认）

2026-11-07，Asia/Shanghai。来源为[R3-03现组合实际验收](../evidence/2026-11-07-m06-zero-app-lifecycle-r1/execution-return.md)。本件只提出具体方案，未修改产品界面、RPC、资源、安装物或R3批准字节，未授权新组合启动。

## 问题与选择

现1c5b/6f2f可原生启停和恢复，但打开M06页面要先创建业务任务；零生成RPC只允许四项只读动作，实际点击报任务创建未完成。放行创建写入会破坏已定零生成合同；预先手写业务快照或返回伪造权威任务也不能作为验收。保留只读门，采用下面的独立预览视图。

## 拟采用行为

1. 复用现有功能中心、M06八输入及来源/结果组件，不重做双来源界面。准确Host明确返回零生成状态时，M06入口展示“只读预览”，点击在客户端本次运行内打开预览视图；不发送`workflow/v340/task/create`、`state/replace`或其他业务写入。
2. 预览页显著说明：“零生成验收：仅核对输入与准备结果，不创建任务、不保存业务草稿、不生成、不登录、不上传或扣费。”它不是业务任务/revision，没有伪造taskId、审核或持久化状态。
3. 可在本次视图内填写八项输入，并通过现有`workflow/v340/prepare`只读公共合同核对明确选择的本项目材料；路径、权限、格式准入、容量与来源/hash仍按原规则。只读模式从Host能力取得，不能仅由URL、客户端开关或用户字段自报。
4. 模型生成、专业API、登录/验证码/刷新登录、上传、审核、结果写回/引用发送等动作不开放。其他正常业务任务入口在此模式下明确禁用及说明，不等点击后才出现通用错误。正常模式继续原任务流程。
5. 关闭视图或应用后不承诺预览输入恢复；它与已有业务草稿、原生未发送对话草稿分开。已有业务/UNKNOWN及审核稿保持原字节，不迁入预览、不改其归属或审核。

## 实施边界与验证

预计只触及既有`workbench-rpc.js`的只读能力返回、`v340-runtime-contract.js`对应可选能力合同，以及`client/workbench-store.js`、功能中心入口和`V340GenerationPage.js`的预览分支。固定业务资源/原规则和四项RPC白名单保持，不新增Provider、Agent循环、存储或启动器。

实施前按实际调用关系收紧准确文件/接口，并以失败用例先证明“打开预览不创建业务任务；材料准备只调用现有只读端点；全部写入/生成仍拒绝”，再做必要回归和实际新归档验证。缺原生Workspace/Host上下文准确拒绝，不用fixture填真实格。新包另版，旧1c5b/6f2f不改、不重签。

确认V0.1仅表示同意该界面行为进入本地实现/离线验证；本次已用的现组合启停授权不自动覆盖未来新包。待准确新包/安装物可审后，再按其具体范围办理零生成启动；真实模型/API/上传/费用、WorkBuddy导入和发布保持未授权。
