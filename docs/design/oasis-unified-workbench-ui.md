# 绿洲统一专业工作台 UI 设计说明（阶段 1 原型 V3.1）

> 日期：2026-09-06<br>
> 状态：待用户确认<br>
> 证据边界：静态交互原型；不代表生产组件、真实 DSH 接线、本地 Skills 或专业 API 已实现。

## 1. 本轮已确认的设计约束

1. 保留原网站的三级任务选择方式：业务域切换、具体任务列表、当前任务高亮。
2. 将任务选择与 Better Sidebar 的功能选择融合，不再建设另一套外部工作台导航。
3. Better Sidebar 首页删除“终端”和“文件变动”；保留“文件”“任务管理”“侧边对话”“浏览器”。
4. 原网站中栏的“输入材料 + 生成结果”进入 Better Sidebar 的侧边工作区。
5. 本地 Skills 与专业 API 共用同一任务、同一表单、同一结果区，仅通过来源开关切换。
6. DSH 原生主对话保留。专业结果通过“在对话中使用”进入主对话草稿，不自动发送。
7. 功能选择页和输入/结果页均作为独立验收画面交付。
8. 输入模块沿用原网站的材料选项卡方式，而不是纵向堆叠全部文本框。
9. 删除非必要解释文案；只在会影响资料去向或费用判断的位置保留简短提示。

## 2. 采用的布局

### 2.1 DSH 主结构不变

- 左侧：DSH 原生工作区、会话和设置入口。
- 中间：DSH 原生主对话。
- 右侧：Better Sidebar，承载功能选择和绿洲专业任务。

不复制 DSH 外壳，不将专业任务改造成第二套独立 Desktop，也不让工作台替换主对话。

### 2.2 Better Sidebar 首页

首页在同一功能中心内展示：

1. **原生功能**：文件、任务管理、侧边对话、浏览器；
2. **专业任务**：保留原网站“技术研发 / 专利撰写 / 辅助工具”切换和具体任务列表。

`Better Sidebar × Oasis` 标识与“功能中心”标题同行靠右；不再显示额外的分区标题、副标题和底部解释。

### 2.3 专业任务页

任务页顶部依次为：

1. 返回功能首页和任务名称；
2. 生成来源开关：宽度充足时位于标题行中间；
3. 简短来源/资料流向提示：宽度充足时位于标题行右侧，宽度不足时进入下一行；
4. 输入与结果工作区；
5. 共同结果操作。

**展开状态**使用左右分栏：左侧输入、右侧结果；标题、来源开关和提示同一行。<br>
**窄栏状态**使用“输入 / 结果”两个视图标签；标题和来源开关在第一行，提示与视图标签在第二行。底部生成操作固定可见。来源切换不重建字段、不清空草稿，也不自动运行。

标题区按 Sidebar 实际容器宽度响应，而不是按整窗宽度或版本标记判断；阈值为 680px，以适应宿主后续调整 Sidebar 尺寸。

### 2.4 输入材料选项卡

输入区参考绿洲慧写 3.0 的 `InputSectionHeader.tsx`、`InputSection.tsx` 和 `index.css`：

- 顶部保留关联项目、新建项目、新会话和布局选择；
- 材料字段显示为可换行的页签，只展示当前页签对应的一个编辑面板；
- 已填写页签显示状态点；当前页签以白底、绿色上边线和连贯下边界表示；
- 支持鼠标及 `ArrowLeft`、`ArrowRight`、`Home`、`End` 键切换；
- 切换页签和切换生成来源都保留全部页签内容；
- “编辑 Markdown / 预览效果”属于当前材料页签，不与窄栏的“输入 / 结果”外层切换混用。

## 3. 任务导航模型

### 3.1 专利撰写

- 权利要求书生成
- 说明书生成
- 申请文件检查

### 3.2 技术研发

- 技术问题拆解
- 候选方案比较
- 验证计划生成

### 3.3 辅助工具

- 材料完整性检查
- 术语一致性检查
- 待确认事项整理

以上仅为原型导航内容，不代表对应 API 已存在或业务 Skill 已交付。生产目录必须由 Host 提供；API 模式仅在实际服务语义和字段映射通过后可用。
V3.1 只展开“权利要求书生成”作为首个业务切片；其他任务显示为“后续模板”，避免用同一套页签伪装成已完成业务绑定。

## 4. 原型公共输入合同

本轮以“权利要求书生成”演示文字型切片，页签顺序与用户截图一致：

| 公共字段 | 控件 | 本地 Skills | 专业 API |
|---|---|---|---|
| 权利要求书 | 选项卡长文本，原型必填 | 作为本地业务输入 | 待实际服务详情确认映射 |
| 技术领域 | 选项卡长文本，可选 | 作为本地业务输入 | 待实际服务详情确认映射 |
| 背景技术 | 选项卡长文本，可选 | 作为本地业务输入 | 待实际服务详情确认映射 |
| 有益效果 | 选项卡长文本，可选 | 作为本地业务输入 | 待实际服务详情确认映射 |
| 具体实施方式 | 选项卡长文本，可选 | 作为本地业务输入 | 待实际服务详情确认映射 |
| 附图说明 | 选项卡长文本，可选 | 作为本地业务输入 | 待实际服务详情确认映射 |
| 用户指令 | 选项卡长文本，可选 | 作为本地业务输入 | 文档示例可对应 User_input，仍需实际详情确认 |

原型不展示可用的文件上传入口。现有项目材料只登记元数据与哈希，不能暗示正文已经参与生成。

## 5. 两种来源的相同与不同

### 相同

- 表单结构、字段值、提交按钮位置；
- 运行状态位置；
- 结果预览、版本、审核、保存 Markdown、在对话中使用；
- 失败后不自动切换来源；
- 生成结果均需人工审核。

### 必须如实显示的不同

- 本地 Skills：使用 DSH 模型设置，可能仍调用用户配置的云模型；不等于离线或免费。
- 专业 API：输入会提交到配置的绿洲服务；提交前显示参考费用和项目绑定。
- API 模式未完成实际服务映射时，生产版本必须禁用，不能用原型示例代替。

## 7. 明确不在本轮原型中的内容

- 真实业务 Skill 正文及装配；
- 真实 API 目录、账户、余额、价格和 folder 绑定；
- 文件正文提取、上传、二进制下载、DOCX/PDF 导出；
- 真实 DSH 设置写入、Profile 修改和安装包二开；
- 终端和文件变动入口；
- 充值、账单、消费记录页面。
