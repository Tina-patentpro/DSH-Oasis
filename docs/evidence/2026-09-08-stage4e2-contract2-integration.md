- Host 接收十字段 JSON，生成含文档信息、核心结论、核心结果、下游读取区、风险与待确认事项的 Markdown。保存实际四项输入，缺失上游明确标记；本批**没有读取或合并上游文件**。
- 本地公开替身生成→人工编辑→重新审核→无覆盖保存→原生文件预览已验证；API 合成结果使用相同成文与审核保存规则。重启后三个版本与四项草稿恢复，已审核 API 合成版本放入原生 DSH 对话草稿，**未发送**。

## 实现与保留

- `patent-claims@2` / `claims-disclosure-2` 为新建任务版本。目录同时保留 `patent-claims@1`，旧七字段和历史哈希不迁移；页面按 ID 与版本精确解析，任务身份不能被替换。
- 本批运行装配资源为独立公开替身 `flow-2-6/public-4e2-1`，不是正式私有文稿 `flow-2-6/0.2.0`。复用既有加载器，固定清单及四资源指纹；Windows checkout 的公开资源固定 LF。清单 SHA-256：`f26448b70bfebe82528d6c207f69881e9a49366270c332ef5f2ed31f4903c9db`。
- 运行只存输入、模型路由、合同和指纹。客户端构建/source map 未检出四个公开指令标记或加载器；包清单 71 项，仅新增公开资源，不含忽略目录中的私有文稿。
- 当前十字段内层采用有界字符串/数组；仅接受当前实际文字来源和可定位原文，拒绝对不存在上游的 replace、伪造继承警示、补齐记录缺失及非法状态。模型建议只作为资料，不替代风险评估或人工审核；编辑后不把旧结构化状态作为权威结论。
- 存储容器仍为 schemaVersion 4。实际保留六个旧任务的表单、工作流、材料、运行及历史顺序。唯一存储形态变化是 workspace-a 原空白 V3 任务经过已有迁移补 `generation:null`；未改变其业务内容、ID 或旧哈希，不能宣称整个存储文件逐字不变。

## 本批发现并修复

1. Desktop 首次准备保存失败 `WRITEBACK_SOURCE_INVALID`：回写来源检查只接受合同 1。先以自动测试复现，再将检查改为工作流版本、输入合同、执行版本与资源指纹配对；不放宽到任意版本。修复后继续保存原已审核版本，没有重新生成。两来源无覆盖保存测试与实际 Desktop 保存通过。
2. 自检发现纯空白正文/摘要可被 JSON 字符串长度检查接收。补充失败用例后拒绝纯空白必需文字，错误仍为固定 `INVALID_OUTPUT`。该最后小改动进行了本地定向复验；没有为此再次创建 Desktop 运行。当前成文函数重算两笔已观察的未编辑公开产物，与保存的结果对象完全一致；此重算不是新的 Desktop/模型调用证据。
3. 旧测试中按“首个同名目录项”取得旧七字段模板的断言改为明确版本 1；新建任务用例改用版本 2。未删去旧版、保全、晚到响应或不确定结果测试。
