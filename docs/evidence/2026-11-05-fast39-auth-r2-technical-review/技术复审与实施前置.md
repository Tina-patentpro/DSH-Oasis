## 2. R2-TR01 例外请求原件与事务意图摘要需明确定义

**P2，阻B提交证据定稿。** [B主稿§2.1](../../business-baseline/fast39-static-authorization-draft-r2/源登记表结构恢复与流程例外草案.md)要求`request_sha256`绑定真实一次性例外意图原件，同时要求使用固定原工具的派生语义。当前没有精确定义原件字节摘要、意图摘要、哪些字段参与计算及两者如何映射。

原工具实际的普通事务算法是：从请求对象排除`expected_revision`和`expected_sha256`，再以`ensure_ascii=False / sort_keys=True / separators=(逗号,冒号)`序列化为UTF-8并求SHA256。它不是请求文件原始字节hash，且基线变化本身不改变此意图摘要。B是另一种被明确标注的例外请求，不能仅因记录仍为六字段形状就默认为采用了同一摘要合同。

本轮纯内存证据显示：同一演示对象的缩进原件、紧凑原件和原工具意图摘要不同；只改演示基线，原工具意图摘要保持不变。更直接的覆盖反例是：仅在当前登记文本的内存副本中将最近事务的`request_sha256`替为64个0，`validate_registration_contract`和`validate_registry`仍返回空错误。它们核格式与绑定，不读取外部请求重算摘要，也不认证批准者、写入者或原子提交过程。**这是既有校验范围，不是本轮发现并要求修复的源工具缺陷。** 实际源及旧事件没有被改动。

解除所需的最小准确绑定：

- 在另版冻结澄清／执行合同中，分别定义请求原件的完整原字节hash与事务中`request_sha256`的计算对象、字段、序列化、编码及排除项，注明机制类别为一次性结构例外。若选择不同于普通事务的摘要语义，必须明确该差异和授权范围。
- 绑定准确批准身份、固定脚本hash、两处变化、真实提交前基线及一次性transaction_id；规定独立重算／核对方法。不能让脚本／意图含自身最终hash产生循环；整册基线的保护仍须单独验证，不能只看意图摘要。
- 原件hash和补充映射可放原执行证据sidecar；保留登记事务六字段及四业务字段边界，不需要扩列、改原工具或重做C4。普通started／结束回执、例外提交回执必须分别如实标注产生机制，禁止拿Schema0冒充执行证明或将例外请求送普通apply。

本轮只提出解除判据，没有生成例外意图原件、脚本或未来真实hash。新澄清必须引用R2准确冻结身份，保留R1／R2原字节，不能原地改文或只改expected来消除问题。

## 3. R2-TR02 普通setup与最终例外请求的冻结阶段需分开

**P2，阻B执行顺序定稿。** 机器草案`execution_sequence`先要求冻结机制／request，再普通started，随后读取post-start真实整册基线；`release_condition`又要求在任何源写入前已有冻结的一次性request。若这里的request均指同一最终准确请求，普通started自身就会改变revision及整册hash：预先冻结的基线不能直接用作started后的基线。当前没有区分“机制／意图模板”和“最终例外提交请求”，不能由执行者自行替换冻结对象。

最小澄清应明确两阶段产物和准许动作：

1. **普通setup前：** 先明确B范围授权、正常CI／治理前置、固定机制脚本／意图模板及普通started自身的准确请求。它只建立新的修复工作项、空grants；不是结构恢复提交。
2. **setup已确认成功后：** 绑定实际started请求／返回、不可变owner／空grants及这一真实新整册基线，再形成最终例外意图、hash、完整差异和准确提交门。只可按事先明确的有界绑定规则派生；若原授权未涵盖该动作或实际变化超出规则，保持停止并补准确批准，不能假称是单纯换expected。
3. **例外提交时：** 再核锁、整册、两处局部字节、目标表、所有旧事件／归属及业务原行；按冻结最终对象提交一次。写后／结果未知只读核对，不另造ID重试。普通结束是另一笔有真实证据的事务。

同时把RESTORE-STOP03的占用条件限定到阶段：源README本来就应存在；成功setup后自身工作项也应存在且须验证同一owner／原行。只有外来／身份不明占用、链接、预期hash不符、新目标冲突或事务ID已使用等才阻新提交；已有本任务证据只能按已确认hash读取或排他追加新件，不能覆盖。这样既不因自己的started而自锁，也不暗许复用他项命名空间。

这不是要求每一步重复人工批准。可以由一份准确授权预先覆盖上述不扩权的两阶段绑定；关键是动作、冻结对象和前后基线明确，并在实施前具证。不能以本轮技术复审代替该授权。
