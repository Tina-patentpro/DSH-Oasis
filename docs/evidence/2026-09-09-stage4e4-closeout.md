## 剩余阻塞：现有文件边界不能保护私有资源

本次只读核对固定本机包，没有让模型或原生工具读取私有正文：

| 普通访问面 | 当前事实 | 影响 |
|---|---|---|
| Sidebar 文件预览/fs.read | `workspaceFence` 可由普通设置关闭；4E-3 已有源码与当前 403 证据 | 工作区外路径不是永久保护 |
| DSH 原生文件工具 | dsh-tool-fs/lib/index.js 约 418 行调用 ctx.fs.streamText/readText | 不受 Sidebar 围栏约束 |
| DSH fs sandbox | dsh-fs-sandbox 明确所有模式允许读取；只覆盖 writeText/editText | 只读模式、工作区写模式都不等于禁止读取私有目录 |
| Windows ACL sandbox | types-DuU3lSVe.js 约 883–884 行明确限制写入，不限制读取、网络与进程可见性 | 不能把现成写沙箱当作私有资源读隔离 |
| PowerShell sandbox | danger-full-access 路径委托非沙箱实现（约 154/187 行） | 不能仅在受限模式加路径检查就声称所有普通执行入口受保护 |

四份固定源码哈希记录在 final-evidence.json。以上为本地固定源码合同证据，不冒充实际提取私有内容。没有关闭围栏、修改 DSH/Sidebar、禁用原生工具、改 ACL 或新建 OS 账号/服务。

## 后续需要的设计决定

下一步应完成**本机资源读取隔离设计**，而不是继续增加复述检查。必须覆盖 Sidebar、DSH 文件工具以及产品提供的任意命令执行；仅藏目录、改文件名、可逆编码或可关闭设置不能作为隔离证明。

在保持本地执行和原生通用工具能力的条件下，候选方向是让私有资源处于与通用工具不同的本机权限域，Host 通过受控内部边界使用资源；不是远端服务替代本地执行。该方案涉及执行身份/进程与权限，尚未设计验证或获扩大系统变更授权，不能静默实施。若仅采用应用层路径保护，也须明确其未覆盖原生命令执行的缺口，不能以此宣布门禁通过。

正式 flow-2-6/0.2.0 装配仍依赖此保护。真实内容验收还需具体模型、数据去向、调用预算授权；本轮未触碰凭据。未提交、推送或发布。
