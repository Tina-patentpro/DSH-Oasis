## 根因与修正

1. `mutateLatest` 原样返回 `committed=false`，调用链未检查便可能继续上传、创建或查询。现在所有内部检查点必须得到提交确认，否则抛出安全的 `REMOTE_STATE_CONFLICT`；不自动重试外部请求，不覆盖并发编辑。
2. 原流程在读取本地材料前就写 `uploading`，上传成功保存回执时又保持 `uploading`。重开无法区分未派发、已上传未保存、已保存回执。现在先读取本地材料，再保存 `uploading` 后才调用上传；保存回执和退回 `prepared` 在同一次业务存储变更内完成。
3. 上传调用返回认证错误不证明未上传；原流程的 `auth-required` 可以再次上传。现在已调用上传后的任何异常均记为 `UPLOAD_OUTCOME_UNKNOWN`，不自动重传。重开遗留 `uploading`，以及尚未提交但遗留 `auth-required` 的记录，也不自动重新上传。调用前发现凭据缺失的既有可恢复路径保持。
4. 已有 Repository 已检查回执字段唯一性、材料引用和哈希，继续复用而不重复实现。本批补充核对回执字段确为服务的文件字段，并对应冻结表单所选材料；不把未知字段、文本字段或另一材料的回执当作本字段已上传。

没有新存储 schema、旧哈希重算、第二个上传引擎、新 UI 或新真实入口。已提交运行仍沿原始 request key 查询，不因本批恢复路径再次创建。已保存的回执可在后续检查点失败、重开后复用。

保守恢复边界：历史 `uploading` 即使实际上尚未派发，也不能仅凭缺少回执证明安全重传；因此不会自动续传。状态记为失败/结果未知不是证明服务器未保存材料。没有远程删除、自动补偿、退款或跨进程互斥承诺。
